Monday practice: useState

The code challenge, the video-lecture challenge, the three study-guide exercises and the practice from the last slide. The code is copied from the files; the output on the right is the real component running.

M1

Code challenge: counter with history

CounterWithHistory.jsx

Goal: build a counter with +1, -1 and Reset buttons, a history of the last 5 values and an Undo button, using two state variables (count and history).

Result: the history is a new array every time ([...prev, next].slice(-5)), never changed in place. Undo goes back to the previous value and is disabled when there is nothing to go back to.

M2

Shopping cart counter

ShoppingCounter.jsx

Goal: show three items with a quantity each (a - and a + button), keep the quantity from going below 0, and show a total from quantity × price.

Result: one state object maps each item id to its quantity. The - button is disabled at 0 and the total is calculated while rendering, so it is never stored.

M3

Toggle visibility

ToggleDetail.jsx

Goal: a “Show details” / “Hide details” button that toggles a paragraph with boolean state.

Result: the button flips isVisible and the paragraph appears and disappears.

M4

Add and remove items from a list

TaskList.jsx

Goal: a text input and an Add button that adds items to an array in state, and a ✕ button on each item that removes it.

Result: items are added with spread and removed with filter, each with a stable id as its key.

M5

Lift state between two counters

ScoreBoard.jsx

Goal: a parent ScoreBoard with two PlayerScore children that shows the combined total.

Result: the scores live in the parent, so it can add them. The children get their value and callbacks through props: data flows down, events flow up.

M6

Live word count

WordCount.jsx

Goal: the practice from the end of Monday’s slides: a live word count under a textarea, using useState.

Result: only the text is state; the number of words is calculated from it while rendering.

Friday practice: useEffect

The code challenge, the three study-guide exercises and the practice from the last slide. Two of these call real APIs, so they need an internet connection.

F1

Code challenge: GitHub user lookup

GitHubLookup.jsx

Goal: an input for a GitHub username and a Search button that fetches api.github.com/users/{name}; show avatar, name, bio, followers and public repos, a loading state and a message for 404. Bonus: abort the previous request.

Result: the effect runs when the searched name changes and its cleanup aborts the request, which is the bonus. 404, a rate limit (GitHub allows 60 requests an hour without a key) and a lost connection each get their own message. Try octocat or the instructor’s muxiddin19.

F2

Page title sync

TitleEditor.jsx

Goal: update document.title as the user types, and put the title back with a cleanup function.

Result: inside this box the title of the embedded page changes as you type; the cleanup restores it before the next effect and when the component goes away.

F3

Fetch a user from an API

FetchUser.jsx

Goal: fetch jsonplaceholder.typicode.com/users/1 and show the name and email, with “Loading...” and error handling.

Result: an effect with an empty dependency array runs once. The async function is defined inside the effect, because an effect callback cannot be async itself.

F4

Stopwatch with cleanup

Stopwatch.jsx

Goal: a stopwatch with Start, Stop and Reset buttons, using setInterval in an effect and cleaning it up.

Result: the interval is only created while it is running, and the cleanup clears it when you press Stop, Reset or leave the page, so nothing keeps ticking in the background.

F5

Live character count with useEffect

WordCount.jsx

Goal: the practice from the end of Friday’s slides: a live character count for an input, using useEffect.

Result: done with an effect as asked. It is only practice: text.length while rendering would give the same number with less code, which is what the “you might not need an effect” slide says.
